# Smart Expense Tracker API

A REST API for managing personal expenses, built with **Java 17 + Spring Boot 3**.

## What this is

A backend service that lets you:
- Add an expense (title, amount, category, date — id is generated by the server)
- View all expenses
- Filter expenses by category
- Get total expenses (overall, or for one category)
- Delete an expense
- Browse/try the API interactively via Swagger UI (bonus feature)

Data is stored **in memory** (a `ConcurrentHashMap`) — nothing is persisted to disk or a database, matching the assignment's "no database required" option. Restarting the server clears all data.

## Prerequisites

- JDK 17 or newer
- Maven 3.8+ (or use the included `./mvnw` wrapper — see note below)

Check versions:
```bash
java -version
mvn -version
```

> **Note on the Maven wrapper:** this repo does not include `mvnw` / `mvnw.cmd` binaries. If your grading environment requires a wrapper and you don't have Maven installed globally, run `mvn -N wrapper:wrapper` once inside the project folder to generate one before following the steps below.

## How to install & run

```bash
# 1. Clone the repo and enter it
git clone <your-repo-url>
cd expense-tracker

# 2. Build (downloads dependencies, compiles, runs tests)
mvn clean install

# 3. Start the server
mvn spring-boot:run
```

The API will be available at **http://localhost:8080**.

Swagger UI (interactive API docs): **http://localhost:8080/swagger-ui.html**

## How to run just the tests

```bash
mvn test
```

This runs:
- `ExpenseServiceTest` — unit tests for the business logic (add, filter, totals, delete, not-found handling)
- `ExpenseControllerTest` — integration tests hitting the real HTTP endpoints via MockMvc (validation errors, 404s, end-to-end add→get→delete flow)

## API Reference

Base URL: `http://localhost:8080/api/expenses`

### Add an expense
```
POST /api/expenses
Content-Type: application/json

{
  "title": "Groceries",
  "amount": 45.50,
  "category": "Food",
  "date": "2026-07-01"
}
```
→ `201 Created`, returns the expense with a generated `id`.

### View all expenses
```
GET /api/expenses
```
→ `200 OK`, array of expenses sorted by date (newest first).

### Filter by category
```
GET /api/expenses?category=Food
```
Category matching is case-insensitive.

### Get a single expense
```
GET /api/expenses/{id}
```
→ `200 OK`, or `404` if the id doesn't exist.

### Total expenses (overall)
```
GET /api/expenses/total
```
→ `{ "category": null, "total": 65.50 }`

### Total expenses (by category)
```
GET /api/expenses/total?category=Food
```
→ `{ "category": "Food", "total": 75.50 }` (returns `0.0` if the category has no expenses — not an error)

### Delete an expense
```
DELETE /api/expenses/{id}
```
→ `204 No Content`, or `404` if the id doesn't exist.

### Example curl session
```bash
# Add an expense
curl -X POST http://localhost:8080/api/expenses \
  -H "Content-Type: application/json" \
  -d '{"title":"Groceries","amount":45.50,"category":"Food","date":"2026-07-01"}'

# View all
curl http://localhost:8080/api/expenses

# Filter by category
curl "http://localhost:8080/api/expenses?category=Food"

# Overall total
curl http://localhost:8080/api/expenses/total

# Total for one category
curl "http://localhost:8080/api/expenses/total?category=Food"

# Delete (replace {id} with a real id from the add/list response)
curl -X DELETE http://localhost:8080/api/expenses/{id}
```

**Note on the `tests/` folder in the assignment spec:** the assignment's example layout shows a top-level `tests/` directory. For a Maven/Java project, tests are conventionally placed under `src/test/java` so `mvn test` can discover and run them automatically — a separate top-level `tests/` folder isn't executable by Maven's build lifecycle. I kept the standard Maven convention instead of a non-functional top-level folder; the *content* requirement (a real, runnable test suite) is met by `src/test/java`.

## Design decisions worth calling out

- **Server-generates the id** (UUID) rather than accepting a client-supplied one, so two clients can never collide on the same id.
- **Category matching is case-insensitive** (`"food"` matches `"Food"`) since users won't reliably type consistent casing.
- **A category total with no matching expenses returns `0.0`**, not a 404 — an empty total is a valid answer.
- **Validation** (`@NotBlank`, `@Positive`, etc.) rejects malformed input (blank title, negative/zero amount, missing date) with a `400` and a clear message, via a `@RestControllerAdvice` global exception handler, instead of letting bad data into the store.

## Known limitations

- Data is in-memory only — restarting the server wipes all expenses.
- No authentication/authorization (out of scope per the assignment).
- No pagination on `GET /api/expenses` — fine for a take-home assignment's scale, would add for a real dataset.
